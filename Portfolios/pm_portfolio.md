## FC Online 라이브 게임 리소스 플래닝 체계 개선

다중 마일스톤 병렬 운영 환경에서, 리소스 시뮬레이션 기반 의사결정 체계를 구축

역할 Development Manager, Client SE Part Lead (~8명) 기간 2025.01 — 2025.11 회사 EA Korea

###### S I T U A T I O N

EA SPORTS FC Online은 월 단위로 다수의 마일스톤이 병렬 진행되는 대규모 라이브 게임입니다. 각 마일스톤은 Pre-Planning → Production → Debugging → Hardening → Live의 단계를 거치며, KR과 CN이 동시에 릴리즈되는 글로벌 운영 환경이었습니다.

###### T A S K

기존에도 마일스톤 관리 체계는 존재했으나, 두 가지 문제가 있었습니다.

###### 리소스 과부하를 사전에 감지할 수 있는 정량적 도구가 부족 — 스펙 범위 조정 시 "감"에 의존하는 구조

스펙 커팅 의사결정에 비교 가능한 시나리오가 없음 — "줄여야 한다"는 합의는 있어도, "얼마나, 어떻게" 줄일지 판단 근거가 부족

###### A C T I O N

###### 1. Milestone Plan 시각화 개선

기존 마일스톤 관리 문서를 기반으로, 각 마일스톤의 진행 단계(Production / Debugging / Hardening / Live)를 날짜 축 위에 병렬 배치하여 한 눈에 파악할 수 있는 간트 뷰로 재구성했습니다.

###### 2. 리소스 시나리오 설계 및 제안신규 기능(Custom Hub) 릴리즈 시, 상황과 제약조건을 고려하여 3가지 시나리오를 직접 설계하고 의사결정자에게 제안했습니다.

시나리오 스펙 범위 일정 리소스 부하

- S1 Full Spec 기존 일정 초과
- S2 Full Spec + 일정 연장 +2주 정상 범위
- S3 Spec Cut (일부 기능 후순위) + 일정 연장 +2주 여유


###### 3. HLE + SvC 대시보드 구축

인력 부하를 정량화하기 위해 HLE(Hour Level Estimation)과 SvC(Service Capacity, 서비스 용량 대비 공수 비율) 지표를 활용한 대시보드를 구성했습니다. 각 기능별로 Server/Client/Book 파트의 공수를 산정하고, 인원 대비 소화 가능 여부를 수치로 표현하여 "감" 대신 "숫자"로 판단 할 수 있는 구조를 만들었습니다.

###### 4. KR/CN 릴리즈 조율

중국 측 POC(Release DD)가 별도로 존재하는 환경에서, 중국 측 요청사항이 KR 일정과 병렬 진행 가능한지, 우선순위는 어떻게 설정할지를 유관 부서와 협업하여 정리하는 역할을 수행했습니다.

R E S U L T

> 스펙 커팅 의사결정이 시나리오 비교 기반으로 전환 — "줄여야 한다"에서 "S3로 가자"로 > 마일스톤별 리소스 과부하 구간을 사전 감지 가능

> SvC 지표를 통해 리소스 초과 여부를 정량적으로 커뮤니케이션

## Project JSY 대규모 스펙 로드맵 체계 설계

15개 파트, 60+개 스펙의 로드맵과 팀별 부하를 한 눈에 관리하는 체계 준비

역할 개발PM 기간 2025.11 — 현재 회사 엔씨소프트

- S I T U A T I O N

엔씨소프트의 신규 프로젝트의 개발을 진행하며 아트/기획/프로그램 등 여러 파트가 여러 개의 스펙을 동시에 진행하는 대규모 프로젝트였습 니다.

- T A S K


스펙들이 어떤 팀에서 언제 진행되는지 종합적으로 볼 수 있는 현황판이 없었음

각 팀의 인력 배분이 적절한지 판단할 근거가 부족 — 어떤 팀은 과부하, 어떤 팀은 유휴 상태인지 파악 불가

A C T I O N

- 1. 스펙 로드맵 반복 설계 처음부터 직접 설계한 로드맵 관리 체계입니다. 9번의 반복 개선을 거치며 실무에 정착시켰습니다.
- 2. 이슈트래커 연동 구조 설계

각 스펙 ID가 사내 이슈트래커의 일감에 직접 링크되도록 구조를 설계했습니다. 로드맵에서 스펙을 클릭하면 상세 진행사항으로 바로 이동할 수 있 어, 거시적 관점(로드맵)과 미시적 관점(개별 태스크)을 자유롭게 오갈 수 있는 체계를 구축했습니다.

- 3. "테트리스" 가능한 리소스 배분 판


스펙 목록 시트: 60+개 스펙을 분류별로 리스트업, 각 스펙의 담당 팀/시작월/완료월/상태/우선순위를 관리

로드맵 시트: 월 단위 타임라인 위에 각 스펙의 진행 기간을 시각화

팀부하 시트: 팀별로 월간 동시 진행 스펙 수를 자동 집계 — 과부하/유휴 구간을 한 눈에 파악

팀별 월간 부하를 시각화함으로써, 특정 팀에 스펙이 몰리는 구간을 사전에 식별하고, 스펙 일정을 조정하여 팀 간 부하를 균등하게 분배하는 "테트 리스"가 가능해졌습니다.

R E S U L T

> 15개 팀의 60+개 스펙 진행 현황을 단일 문서에서 파악 가능 > 인력 과부하/유휴 구간을 사전 식별하여 일정 조정에 활용 > v1부터 v9까지 반복 개선하며 실무 도구로 정착 — 프로젝트 전체가 동일한 현황판을 참조

- Daeho Choi — Dev PM Portfolio 04


## Project OS 신규 프로젝트 프로덕션 체계 수립 & 게임 기획

Vertical Slice부터 프로덕션 방법론을 설계하고, 기획자 부재 시 직접 UE5로 시스템을 기획/프로토타이핑

역할 Associate Production Director (APD) 기간 2023.01 — 2025.01 회사 콩스튜디오코리아

- S I T U A T I O N

콩스튜디오코리아에서 신규 액션 어드벤처 프로젝트의 APD로 합류했습니다. Vertical Slice부터 Shipping까지의 전체 프로덕션 로드맵을 세우고 실행해야 하는 단계였으며, 소규모 팀 특성상 PM이 기획 영역까지 직접 커버해야 하는 환경이었습니다.

- T A S K


프로젝트의 마일스톤 체계와 프로덕션 방법론을 처음부터 정의해야 함

Task Management System(TMS)이 정리되어 있지 않아 일감의 위계와 추적 체계가 필요

기획자 부재 상황에서 파쿠르 시스템, 레벨 디자인 등 핵심 피처를 직접 기획해야 하는 상황

A C T I O N

- 1. 하이브리드 프로덕션 방법론 설계 (Waterfall + Agile) 상위 계획은 Waterfall, 실행은 Agile로 분리하는 하이브리드 구조를 설계했습니다.
- 2. Task Management System 구성 (Airtable) Jira 대신 Airtable을 활용하여 자유도 높은 TMS를 구성했습니다.
- 3. 커뮤니케이션 체계 정비
- 4. 게임 기획 직접 수행 (UE5) 담당 기획자가 없는 피처를 직접 기획하고 UE5에서 프로토타이핑했습니다.


Milestone / Initiative: 상위 레벨에서 명확한 목표와 달성 기준을 Waterfall로 설정

Epic / Task / Subtask: 실행 단위는 Agile하게 반복 수행

Vertical Slice → Alpha → Beta → Shipping까지 세부 단계별 달성 필요 사항을 정의

Task의 위계(Objective → Epic → Task → Subtask) 세팅

리스크 요소 파악을 위한 중요도 체크(자체 중요도, 연관성, Plan B 유무)

빠른 PoC를 통한 검증 우선 방식 적용 (MVP → QA → 이터레이션)

회의 전 Agenda 사전 공유, 발산/수렴 성격 미리 정의

Action Item 추출 중심 회의 운영

회색 영역(담당자가 애매한 업무)을 식별하여 프로젝트화

파쿠르(클라이밍/볼팅) 시스템: 상태 전이 다이어그램 + 상세 기능 명세서 작성 → 유관 부서 킥오프 → 구현 → 이터레이션

레벨 디자인: 약 2시간 플레이타임 규모의 필드 동선/클라이밍 루트 기획, 30분 분량 던전 레벨 기획 (기믹/연출 포함)

연출 프리비즈: UE5 BP, 카메라, 시퀀서를 활용하여 인게임 타이밍과 느낌을 사전 구현 → 실 작업자가 퀄리티를 높여 마무리

R E S U L T

> Vertical Slice 마일스톤 달성 — 기획자 부재 위기에서 직접 기획 + 프로토타이핑으로 첫 목표 완수

> 하이브리드 방법론과 TMS 구조가 프로젝트 전반에 표준으로 정착 > PM이면서 기획/레벨디자인/연출까지 직접 수행 — "직접 만드는 PM" 역량 증명

## ZEPETO IP 제휴 콘텐츠 WBS 표준화

글로벌 IP 제휴 프로젝트를 A-Z 스케줄링하는 WBS 템플릿을 처음부터 설계

역할 콘텐츠 PM 기간 2022.06 — 2023.01 회사 NAVER Z

- S I T U A T I O N

NAVER Z의 제페토에서 글로벌 IP(BTS, 현대자동차, 나이키 등)와의 제휴 아이템 제작을 담당했습니다. 컨셉 논의 → 원화 → 모델링 → QA → 릴리즈까지 순차적으로 진행되는 프로젝트가 다수였으나, 중간에서 전체 과정을 취합하고 정리하는 역할이 부재한 상태였습니다. 특히나 태스크 매니지먼트 시스템을 팀별로 다른 서비스를 통해 진행 중이어서, 중간 컨트롤타워가 반드시 필요한 상황이었습니다.

- T A S K


각 팀별로 "어디까지 됐어요?" 라는 질문이 반복 — 진행 현황을 알려면 매번 개별 확인 필요

새로운 제휴 니즈가 발생할 때마다 A-Z 스케줄링을 처음부터 다시 하는 비효율

A C T I O N

- 1. WBS 템플릿 설계 (처음부터) 제휴 아이템 제작의 전체 프로세스를 단계별로 정의하고, 표준화된 WBS 템플릿을 처음부터 설계했습니다.

Stage Task 자동화

컨셉 논의 아이템 컨셉 논의, 기획서 작성, 컨펌 기획 시작일 자동 역산

원화 작업 스케치 → 1차 원화 → 컨펌 M/D 기반 일정 산정

모델링 3D 제작 → 리뷰 → 수정 실제 작업일 자동 계산

QA 기능 테스트 → 수정 → 최종 확인 —

릴리즈 베타 등록 → 라이브 배포 옵션별 분기

- 2. 자동 일정 산정 구조

릴리즈 타겟 날짜만 입력하면 각 단계의 시작일이 자동으로 역산되는 구조를 구현했습니다. 월드 연계 여부, 영상 제작 여부 등 옵션에 따라 일정이 자동 조정되어, 새 프로젝트 시작 시 스케줄링 시간을 최소화했습니다.

- 3. 제휴처 직접 커뮤니케이션


사업팀뿐 아니라 제휴처 담당 인원들과도 직접 소통하며, 제작 진행 상황 공유, 필요 정보(레퍼런스, 라이선스 가이드라인 등) 요청, 일정 조율을 수 행했습니다.

R E S U L T

> "어디까지 됐어요?" 커뮤니케이션 비용 대폭 감소 — 수치적으로 진행률과 일정을 볼 수 있는 현황판 확보 > 여러 제휴 프로젝트에 동일 템플릿 적용, 프로세스 안정화

###### > 새 프로젝트 착수 시 스케줄링 소요 시간 단축

## TIKIT PM이 직접 빌딩한 AI 서비스

코드를 못 쓰는 PM이 AI 에이전트와 함께 기획~개발~브랜딩~배포까지 혼자 완수
