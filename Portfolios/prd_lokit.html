01 — Product Vision

받는 사람을 위한
잠긴 선물카드

LOKIT은 보내는 사람이 비밀번호·단서·선물을 묶어 카드를 만들고, 받는 사람이 단서를 풀어 잠금을 해제하는 모바일 웹입니다. 카드는 링크 하나로 전달되며, 가입·설치 없이 0-마찰로 주고받을 수 있습니다.

"기프티콘 한 장도 풀이 경험을 얹으면, 전달 맥락 자체가 콘텐츠가 된다."

Core Value Loop

① Host가 /create에서 카드·비밀번호·단서·선물을 설정
② /l/<id> 링크를 받는 사람에게 공유
③ Player가 카드를 "발견" → 단서를 보며 비밀번호 유추
④ 정답 시 선물 공개 + /my 선물함에 기록
⑤ FCFS의 경우 "몇 번째로 풀었나" 랭크 → 이벤트성·경쟁성

핵심 차별점

🎮

풀이 경험을 얹은 보상

폼 입력 → 추첨이 아닌, 추리 → 해독 → 보상 획득의 능동적 게임 루프.

🎚️

스펙트럼 유연성

단서 1개의 가벼운 선물부터, 다단계 단서 + 선착순 보상의 본격 이벤트까지 동일 플랫폼.

🔗

무로그인 링크 기반

iOS Safari / Android Chrome 모바일 웹 단일 링크. 가입·설치 0-마찰.

✨

앱 수준 인터랙션

Glass-morphism + Framer Motion 기반 3D 플립카드, 흔들림, confetti.

02 — Problem Definition

기존 선물·이벤트 도구의 한계

온라인 이벤트/기브어웨이 도구는 참여자에게 재미가 없고, 운영자에게 차별화 수단이 없습니다. 카톡 기프티콘 직송도 받는 순간이 밋밋합니다.

기존 방식문제
댓글 추첨참여자 수동적. "댓글 달고 기다리기"의 반복. 운영자는 인게이지먼트 수단 없음
구글 폼/타입폼정보 수집 목적. 참여 자체에 재미 요소 없음. 응모 → 추첨의 트랜잭션 구조
퀴즈 플랫폼실시간 동시 접속 전제. 비동기 이벤트에 부적합. 보상 배포 기능 약함
선착순 링크 공유단순 속도 경쟁. 봇 어뷰징에 취약. 참여 경험이 빈약
카톡 기프티콘 직송받는 순간이 밋밋. "한 겹의 재미"를 더할 도구 부재

LOKIT의 해결

"추리 → 해독 → 보상"의 게임 루프를 선물·이벤트에 도입. Player는 능동적 성취감을, Host는 이벤트/선물 자체가 콘텐츠가 되는 바이럴을 얻습니다.

04 — Personas & Use Cases

타겟 유저 & 시나리오

Primary — Host / Maker

🔧 보내는 사람

누구30대 전후 모바일 사용자. 커뮤니티 운영자, 인플루언서, 이벤트 기획자, 소규모 브랜드 마케터, 또는 친구·연인·팀원에게 의미 부여하고 싶은 일반 사용자
Pain Point댓글 추첨은 식상, 구글 폼은 재미없음, 카톡 기프티콘 직송은 밋밋. 이벤트/선물 자체로 화제가 되는 경험을 만들고 싶음
기존 대안인스타 댓글 추첨, 구글 폼 + 랜덤 추첨, Gleam.io, 카카오톡 선물하기, 편지 앱
LOKIT이벤트/선물 = 콘텐츠. 단서 공유 과정 자체가 바이럴. 받는 사람이 맞히는 재미로 관계성 강화
Secondary — Player

🎯 받는 사람

누구Host와 동일한 디바이스 프로필. 게임 요소를 즐기는 일반 사용자. 이벤트/기브어웨이에 관심이 많은 MZ세대
Pain Point기존 이벤트는 "댓글 달고 기다리기"뿐. 내가 뭔가를 해서 보상을 획득하는 성취감이 없음
기존 대안댓글 이벤트 참여, 퀴즈쇼 시청
LOKIT단서 조합 → 정답 → "내가 풀었다"는 성취감 + 보상 + (FCFS) 랭크

사용 시나리오 스펙트럼

대규모 이벤트만이 아닌 일상의 선물과 소통까지 — 단서 1개·질문 1개로도 기프티콘 한 장을 특별한 경험으로.

시나리오예시
일상 선물기념일에 연인에게 기프티콘. "내가 좋아하는 색은?" → 정답 맞히면 스타벅스 쿠폰
생일 쿠폰"숫자 4자리 = 상대 생일". 단서: "우리 처음 만난 해 뒤에 13 붙이면 돼"
팀 이벤트FCFS 10명, 커피 쿠폰 링크. 단서는 회사 내 공통 밈
기념일 편지텍스트 비밀번호. 선물은 이미지/파일 첨부
커뮤니티인플루언서가 팔로워 대상 다단계 단서 이벤트. 참여자 간 추리 공유
브랜드 마케팅"제품명을 맞혀라" 캠페인. 선착순 N명에게 할인 코드
오프라인 연계매장/팝업스토어 QR 배치. 현장 보물찾기 (QR은 로드맵)
05 — Goals & Metrics

목표 & 성공 지표

Goals (현재 이터레이션)

  • 가입 없이 30초 안에 카드 생성 → 공유 링크 확보가 가능할 것
  • 받는 사람이 링크 탭 → 10초 안에 풀이 시작이 가능할 것
  • 비밀번호/단서/선물 구조가 확장 가능한 레지스트리로 관리
  • iOS Safari / Android Chrome에서 무결 동작 (3D 플립·글래스 인풋 포함)
  • Glass-morphism + Framer Motion에서 시각 품질 타협 없음 — 앱 수준 인터랙션

Non-Goals

  • 회원 가입 / SNS 로그인 / 비밀번호 재설정 — 익명 UID로만 식별
  • 호스트 대시보드, 실시간 알림, 결제, 기프티콘 발급 연동 (로드맵)
  • 데스크톱 최적화 — 모바일 퍼스트 (max-w-md)
  • 다국어 — 한국어 단일 (Pretendard Variable)
  • 실시간 멀티플레이어 동시 경쟁 — 비동기 풀이가 본질

07 — Functional Spec

핵심 동작 명세

Password verification verifyPassword

순서가 중요하다 (코드 주석 기준):

  1. claims에 (locker_id, player_id) 존재 확인 → 있으면 already_claimed
  2. lockers 조회. 없으면 not_found, status='exhausted'면 exhausted
  3. 비밀번호 불일치 → wrong_password
  4. claims.count로 새 rank 계산
  5. FCFS 가득 찼는지 삽입 전에도 체크 → 차면 exhausted 처리
  6. claims.insert({locker_id, player_id, rank})
  7. 삽입 후 rank >= reward_limit면 status='exhausted'로 플립
  8. 성공 응답에 reward_* 본문 포함

Hints useHint

  • 인덱스 규약: hintIndex = 0 → clues[1] (기본 단서 제외 순서)
  • 세션 lazy-create: 없으면 player_sessions에 hint_points=3으로 삽입
  • 이미 연 힌트면 포인트 재차감 없이 동일 content 반환
  • 포인트 부족(hint_points < cost) → insufficient_points
  • 성공 시 hint_points -= cost, hints_unlocked 배열에 인덱스 추가
  • 재충전: 클라 타이머만 (서버 자동 재충전 미구현 — last_point_recharge 컬럼만 존재)

Public DTO 경계 getLockerPublic

  • 포함: id, name, sender_name, password_type, reward_type, reward_limit, reward_title, hint_point_cost, total_clues, base_clue, status, claim_count, active_players
  • 제외: final_password, reward_content, reward_description, 힌트 본문, reward_file_url
  • 성공한 VerifyResult에서만 reward_* 본문 노출 — 이 경계가 보안 1차 방어선

레지스트리 확장 규약 PASSWORD_TYPES · CLUE_TYPES

  • 새 비밀번호 타입 추가 → PASSWORD_TYPES에 한 줄 + schema.sql의 check 제약 alter
  • 현재 password types: numeric / text / date
  • 현재 clue types: text만. 미래 후보 image, audio 자리 준비
  • 레거시 row 호환: type 없는 row는 normalizeClueType()로 'text' 기본
08 — Data Model

데이터 구조

lockers main

  • id uuid pk, name, description, sender_name
  • password_type (numeric/text/date), final_password (평문)
  • reward_type (unlimited/fcfs), reward_limit
  • reward_title, reward_description, reward_content, reward_image_url, reward_file_url
  • clues jsonb — [{id, type, content, order}]
  • hint_point_cost, status (active/exhausted/expired), visibility
  • created_by text (익명 UID, indexed)

claims picked

  • (locker_id, player_id) unique
  • rank int — claim 순번 (FCFS "몇 번째로 풀었나")
  • claimed_at timestamptz

player_sessions hints state

  • (locker_id, player_id) unique
  • hint_points int default 3, hints_used, hints_unlocked int[]
  • last_point_recharge (서버 로직 미구현), joined_at

Storage & RLS

  • 버킷 rewards (public). 경로 ${creatorId}/${ts}-${filename}
  • RLS: 세 테이블 모두 enabled but policy = all-allow ("tighten later" 코멘트)
  • 마이그레이션: schema.sql 하단에 alter table ... if not exists 누적, Supabase SQL Editor 수동 실행
